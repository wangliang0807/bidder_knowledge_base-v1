# ADR-001：投标人知识库管理系统综述

> 日期：2026-09-18
> 状态：设计中

## 概述
这是一个在互联网（租赁环境）部署的应用系统。部署在租赁的阿里云服务器及存储上，一台虚拟服务器供所有投标人使用，对投标人做逻辑隔离。

与v2系统的关系：
- v2是代客编标公司的内部系统，不对投标人开放。
- 为了简化投标人注册，由v2代本系统产生投标人账号，两个系统的账号实际没有关联。
- 招标项目也由v2用户分析后录入，投标人在本系统看到的项目名是规范的 —— 免得投标人不会用，或输错投标项目名，导致两边数据对不齐。

其实现目标为：
1. 投标人与v2系统的纽带，解决投标人无法自己传输、整理资料的问题。
2. 投标人自身的知识积累，解决每次投标都要重新整理资料的痛点。
3. 作为投标人的知识库，可以解答『某投标项目要求「近三年2000万业绩不少于5个」，我能不能投标』之类的问题。 
4. 投标人也可以上传诸如管理制度、财务制度、施工工艺、常用国标、行标等等与投标项目有直接或间接关系的文档。在投标人制作某项目投标文件时，将这些文件指派给标书制作者，让标书更严谨、更规范、更贴近公司事实。
5. 证件有效期管理。可以提醒投标人哪些证件即将到期。
6. 资料图片规范化。可以帮助投标人对其提交的证件等扫描件进行格式规范化，解决诸如：size太大，图片边框太多，方向不对，字迹模糊等问题。

## 核心功能

### 系统功能
1. v2系统与本系统对接及数据传输
数据传输请求为单向：只能从v2服务器到本系统服务器，而本系统没有数据传输的请求权利。
数据采用push（向本系统服务器推送）/pull（从本系统服务器拉取）
push例子：
 - 投标人用户在v2系统产生，用户名是：手机号@公司简称。数据由v2服务器传输给本系统。用户登录本系统，采用短信验证。
 - 投标人可以投的招标项目。用户在v2系统读取招标文件后，把投标人设置为该项目的拟投标人。评分细则等一并传输给本系统。
pull例子：
 - 投标人整理招标项目的资料后，把资料打包并上传（做上标记）。然后v2系统主动发现数据，把数据pull到v2系统。
pull的具体做法：本系统提供一个地址供v2定期访问，返回json。返回 [] 表示没有新资料；返回 [{"id": "xxxxxx"}] 表示有待下载的资料，v2据此逐个编号下载，本系统把资料zip后传输给v2。

2. 本系统的AI统一使用DSH。需要处理的文件类型很多，还要支持CAD。本系统不做CAD解析 —— 不是专业CAD公司，不用看懂CAD，只要能把CAD转成jpg并打上tag就可以（tag里写明这张图是什么，如「三楼平面图」「监控布点图」），v2据此把jpg插入到正确的位置。

### 投标人功能
#### 基本功能
1. 一个投标人可以开通多个账号。同一投标人的账号看到的、能做的都一模一样。
2. 登录本系统。采用短信验证登录。token失效期：12小时。
3. 工作台：档案柜、文件柜、拟投标项目柜
4. 投标人首次登录系统，工作台上只能看到拟投标项目和空的缺省资料档案柜（公司、人员、业绩、设备、其他）以及「回收站」

#### 文件管理
1. 用户工作台有文件区，保存着用户上传的原始文件。
2. 用户可以将一个或一批原始文件让AI处理成一个或一批档案袋(原子)
3. 原始文件的去留由投标人自己定：觉得文件太多了就丢回收站，没几个文件留着也行。

#### 档案管理
1. 用户不能删除缺省的五个档案柜。
2. 用户可以创建新的档案柜，并取名。也可以删除创建的档案柜；删柜时柜内档案袋的处置待定 —— 偏安全则要求清空后才能删柜，偏方便则允许连柜带元素一起删。
3. 用户可以在档案柜里创建档案分类和子分类，分类和子分类里面可以存放档案袋，一个档案袋对应一则资料（物理文件与v2系统的原子资料同构），档案袋有tag（做法与v2的.tag相同：json，记录类别、关键信息和内容组成，供AI不必打开原文件就知道这份资料是什么），tag由本系统的DSH生成。
4. 用户可以针对一个档案袋（含一个或一批文件），进行标准化处理。标准化处理就是图片处理：
   - AI做的：歪的、斜的、反的证件图给它摆正；切片正好贴合证件大小。
   - 系统做的：size超标的，把png转jpg、分辨率缩小。
   这项功能不追求一次做到位 —— 想到什么就做什么，版本可以升级。
5. 用户可以移动档案柜三要素：分类、子分类、档案袋。柜内移动或者柜间移动。
6. 每份档案袋都有独一无二的编号。
7. 档案袋被有效引用时不能删除：有效引用 = 编号被某个尚未到开标日期的投标项目引用（两个条件同时成立）；项目过了开标日期，引用随之失效，档案袋不再受限制。
8. 删除的档案袋进入「回收站」；「回收站」与 Windows 回收站性质相同：可以还原，也可以清空，清空即彻底删除。
9. 有一个总的档案清册（csv或者yaml，待定），记录着每份档案袋的柜、分类、子分类和其他属性。系统或AI可以只看清册，就能知道投标人的所有资料情况。清册是给本系统的AI用的，知识问答即以清册为数据源。

#### 拟投标项目管理
1. 选中某投标项目，点击资料整理。逐档案柜选中档案袋。然后按打包发送。（系统实际产生了一个档案编号清单）
2. 投标人在选中档案袋后可以加上附语，随打包一并发送给标书制作者。附语是投标人口头交代的代位：原先资料经微信转交、投标人可顺口说明，现改为本系统直达，说明改由附语承载。附语所挂的资料是投标人的额外资料 —— 不是投标文件所需的证明材料，而是供编写者参照的公司制度、施工工艺、国标行标等。附语示例：「XXX项目投标技术方案编写时必须严格遵守本标准，不得出现有违背本标准的描述。」附语和所附文件的最终去向是v2的深化大纲与正文环节：系统直接把附语和文件传给LLM或DSH（v2即将改进的功能）。
3. 附语的遵从顺序：招标文件 → 附语（本标准）。招标文件永远第一。
4. 系统自动过滤已过开标日期的项目到历史项目。

#### 临过期资料处理
1. 证件的有效期由OCR自动提取，记入档案袋的tag。
2. 用户可以设置某分类、某子分类、某档案的临期提醒（可以设置：前X个月）。有的证换证周期长（有的要半年），提醒时间要由人来设置。
3. 系统显示临过期资料清单。
4. 用户一般会换证，然后将新证上传，重新编入档案，再把旧证废掉。

#### 知识问答
1. 用户可以向AI提问，比如：「我公司能否参与XXX项目的投标，现有人员和业绩的得分情况」。
2. 但问题只能限制在本公司。不能问：「XXX公司有几个业绩？」
